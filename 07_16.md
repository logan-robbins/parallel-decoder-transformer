# Model-Intrinsic Parallel Generation: July 16 Architecture And Real-Data Plan

## Scientific Decision

PDT uses one shared frozen transformer trunk with three simultaneous physical
continuation lanes. Each lane has its own token frontier, KV state, latent
outline, and bus address. One packed trunk call processes all three rows and
returns three next-token distributions. Three independently parameterized
trunk copies are not required for concurrent lanes and are not the canonical
architecture.

The factorization is valid when, conditioned on the static plan and notes
published before the current synchronization block, the three current tokens
do not depend on one another. Same-round cross-lane dependencies are rejected.
Cross-lane information arrives through delayed embedded fragments at the next
block boundary.

The visible result is three multi-paragraph sections rendered in planner
presentation order. There is no fourth serial synthesis pass. D1, D2, and D3
are physical addresses; their semantic responsibilities vary by prompt.

## Architecture

The planner runs once on the shared prompt and source. It uses three groups of
eight learned queries to cross-attend over the frozen prompt hidden states and
produces a continuous tensor shaped `[B, 3, 8, 512]`. The three plan groups are
an unordered set. Exact enumeration over the six possible lane permutations
matches them to three teacher plans during training.

Each matched lane receives its own eight-node outline as persistent, read-only
memory at every instrumented trunk layer. Generated tokens never update or
re-enter the planner. At each 32-token boundary, the existing speculation head
encodes the completed block into four 8-bit product-code indices. These delayed
dynamic notes describe generated fragments and let sibling lanes avoid
duplication or integrate prior material without transporting full text.

The current per-stream adapter bank is replaced by one shared
plan-conditioned bottleneck adapter per instrumented layer. A pooled outline
state produces FiLM scale and shift parameters for the shared bottleneck.
Physical lane IDs remain only in KV ownership and addressed bus metadata, so
adapter parameters cannot memorize permanent semantic roles.

Inference and training both use one packed frontier. Inference consumes one
token per lane per trunk call. Teacher-forced training consumes one 32-token
block per lane in a single `[B*3, 32]` call and publishes the three block notes
atomically.

## Source-Grounded Data

The first corpus is deliberately restricted to reliable historical events and
processes. Arbitrary Wikipedia pages, biographies as the primary topic, lists,
timelines, chronologies, year pages, outlines, current events, and narrow
catalog-like pages are inadmissible.

The existing Hugging Face Wikipedia sampler is rejected for real training. It
loses heading/citation relationships and truncates oversized articles to an
early prefix. It must not be used for source generation or paid Batch input.
The replacement ingress pins a Wikimedia page revision and retains immutable
raw wikitext, rendered semantic HTML, PageAssessments data, and parsed
reference metadata.

Model-visible source text is produced by a strict DOM allowlist. It contains
only the article title, hierarchical content headings, and ordinary prose
paragraphs. Inline links contribute only their human-readable display text.
The renderer excludes tables, lists, infoboxes, templates, figures, captions,
galleries, maps, coordinates, citation markers, footnotes, bibliography text,
URLs, navigation, categories, authority control, hatnotes, pronunciation,
math, code, and edit artifacts. It excludes entire References, Notes,
Citations, Sources, Bibliography, Further reading, External links, See also,
Gallery, and equivalent subtrees. Citation IDs and bibliographic records remain
separate audit metadata and are never concatenated into the student prompt.

An accepted article must be an English main-namespace, non-redirect,
non-disambiguation event or process that ended at least 25 years before the
pinned dump. It must be attached to a history-oriented WikiProject with
relevant `FA`, `GA`, `A`, or `B` quality. The complete cleaned body must
naturally contain 3,000-7,000 pinned-Qwen tokens, at least six substantive
sections, and at least twelve substantive paragraphs. No prefix truncation or
fragment stitching is allowed.

Citation quality is a hard gate. Each accepted article requires at least 30
inline reference occurrences, 15 distinct cited works, eight identifiable
books, journals, archives, or institutional publications, citations on at
least 70% of substantive paragraphs, and no single work responsible for more
than 25% of occurrences. Maintenance templates for missing citations,
neutrality, disputed accuracy, original research, cleanup, or hoaxes cause
rejection. Each normalized paragraph stores reference IDs outside its text,
and every accepted fact must map its exact quote to at least one of those
references.

Two asynchronous Batch stages produce strict structured output:

1. Extract 18-48 atomic cited facts, relations, importance, hard
   contradictions, and exact source-paragraph/reference provenance.
2. In one joint request, create exactly three complementary unordered plans
   and all three target sections. The streams are never generated by
   independent teacher calls.

Each plan contains four to eight ordered outline nodes. Each node records its
objective, owned facts, permitted reference facts, cross-plan dependencies,
and target paragraph spans. Each target stream contains 700-1,000 tokens in
multiple connected paragraphs. Every fact/lane/block label is one of
`OWNER`, `REFERENCE`, or `ABSENT`. Stored teacher-plan order is randomized,
and no textual plan or role hint enters a lane prompt.

Near-duplicate and related historical topic families are clustered before
splitting, and a complete family belongs to one split. Article-ID hashing alone
is not an admissible leakage defense. The 128 accepted pilot examples are
balanced across wars/battles, revolutions/transitions, treaties/crises, social
movements/reforms, exploration/migration, scientific/industrial developments,
disasters/reconstruction, and cultural/institutional transformations.

The fact stage is the cheap paid filter. Only articles that pass cited-fact
validation and constrained three-way decomposition feasibility receive the
larger joint-generation request. Every accepted pilot record is manually
inspected. The architecture gate contains 2,048 examples; a 20,000-example
corpus is forbidden until that gate shows value.

## Objective

After selecting the minimum-cost lane permutation, optimize:

`L = 1.0 L_token + 1.0 L_plan_semantic + 1.0 L_fact_route
     + 0.5 L_outline_progress + 1.0 L_fact_write
     + 0.25 L_note_align + 0.10 L_presentation_order
     + 0.25 L_dynamic_commit + 1.0 L_dynamic_codebook
     + 0.10 L_dynamic_usage`.

`L_token` is exact per-lane next-token cross entropy. `L_plan_semantic`
aligns predicted outline nodes with frozen teacher-outline embeddings.
`L_fact_route` assigns atomic facts to plan nodes. `L_outline_progress`
identifies the outline node expanded by each generated block. `L_fact_write`
classifies every fact against every lane/block as owner, reference, or absent.
Positive and paired hard-negative fact queries enter both routing and write
supervision. Route loss balances positive and negative queries; write loss
balances owner, reference, and absent classes so the objective cannot collapse
onto the majority absent label. `L_note_align` contrasts each dynamic write
with other stream/block writes in the packed document. Presentation-order loss
determines rendering order.
Only dynamic notes retain VQ losses; the structured outline stays continuous.

A fact-query coverage head cross-attends frozen fact embeddings to output
hidden states. Hard negative facts alter dates, entities, quantities, or
relations. Whole-answer embedding similarity is not an admissible substitute:
facts must be written by their assigned physical lane.

## Curriculum And Evidence

First train an oracle-outline executor control by injecting frozen teacher
outline embeddings while the planner and trunk are frozen. Next freeze the
executor and train the planner to reproduce the unordered outline set. Finally,
keep the trunk frozen and train the planner and all shared sidecar mechanisms
end to end through the packed rollout. Oracle-outline runs are controls, not
PDT results.

The causal attribution suite includes complete-plan swaps, plan zeroing,
random plans, an address-only control, source-note swaps, and gate-zero
interventions. Swapping D1 and D2 plans must swap their fact ownership.
Combined-answer coverage never replaces per-lane owner recall, unauthorized
wrong-lane leakage, reference timing, duplication, and outline completion.

The 128-example oracle control must reach at least 90% owner-fact recall, at
most 10% unauthorized leakage, and at least 90% outline-node completion.
Plan swaps must transfer at least 80% of affected owner facts. On held-out
data, the learned planner must retain at least 80% of oracle owner recall,
plan zeroing must reduce owner recall by at least 30 percentage points, and
dynamic-note ablation must selectively harm annotated later references.

If the shared 4B oracle executor fails, repeat the identical architecture with
the dense 14B trunk before adding lane-specific capacity. Three independent
trunk copies are considered only after both shared-trunk oracle controls show
a capacity-specific failure.

## Implemented Evidence Surface

Retokenization materializes the exact Qwen token positions overlapped by every
required dependency evidence quote and rejects any edge whose complete source
evidence block is not visible before the first receiver-evidence block.
Teacher-forced causal evaluation removes
only dynamic notes, preserves the complete static plan path, and compares
normal versus ablated negative log likelihood at those exact dependency tokens
and at the complementary nondependency tokens. It retains per-document effects
and deterministic document bootstrap intervals. Unit tests validate alignment
and aggregation but never set or claim an empirical effect.

Free-generation evaluation freezes one BGE similarity threshold on a disjoint
teacher-prose calibration split. Stage-0 checkpoints run the oracle-plan
executor condition. Stage-1 and later checkpoints run oracle, learned,
plan-zero, and physical D1/D2 plan-swap conditions. Learned outlines are
matched to teacher outlines before facts are mapped to physical addresses. A
fact emitted by an unauthorized lane cannot rescue owner recall. The swap is
scored both at the expected moved addresses and at the deliberately wrong
unmoved addresses.

Natural generation decodes each lane until its own EOS or the 1,000-token
ceiling. Finished lanes remain physically present in the three-row cache but
are logically masked, so completion does not fall back to separate decoder
calls. Long-form checks require at least 700 generated tokens, four paragraphs,
and a low short-sentence rate for every lane.

The parameter-matched self-only model uses the same persistent plan memory and
the same per-layer parameterization, but its communication read contains only
the receiver's delayed block-end states. It is trained and checkpointed as a
separate scientific condition.

## Handoff And Exact Next Steps

The implementation does not establish that the architecture works. No
real-plan example has been generated, no paid historical Batch request is
authorized, and no H100 run should begin from the current source sampler.

1. Replace `scripts/prepare_wikipedia_sources.py` with pinned-revision
   Wikimedia wikitext plus rendered-DOM ingress.
2. Extend the raw source schema with heading paths, paragraph-local reference
   IDs, parsed references, revision identity, assessment metadata, and
   deterministic rejection reasons. None of these metadata fields enter the
   student-visible rendering. Publish new schema identities:
   `pdt-historical-source-v1`, `pdt-real-plan-v2`, and
   `pdt-real-plan-tokenized-v3`; old raw-v1/tokenized-v2 rows are inadmissible.
3. Implement the historical-event, quality, full-body length, structure,
   citation-distribution, scholarly-source, maintenance-template, and
   completeness gates above.
4. Implement family-level deduplication and split assignment before sampling.
5. Add golden and adversarial parser fixtures proving that only headings and
   prose can reach model-visible text. Make the Batch builder require the
   exact SHA-256 of the resulting accepted manifest.
6. Select the balanced pilot candidates, run the cheap fact stage, and reject
   any article without 18-48 cited facts across twelve paragraphs and four
   sections or without a feasible three-way decomposition.
7. Run joint generation only for qualifying candidates, produce 128 accepted
   examples, and manually inspect every record.
8. Freeze the pilot schema, renderer, prompts, manifests, and rejection report;
   then retokenize and run the single-H100 two-update optimizer probe.
9. Test the oracle executor before the learned planner and dynamic bus. Expand
   to 2,048 only after the data and oracle gates pass. Consider 20,000 only
   after the architecture shows value.
